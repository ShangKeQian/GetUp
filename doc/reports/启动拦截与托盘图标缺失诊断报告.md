## 三、问题 1：启动被拦截

### 3.1 因果链（最可能）

```
图标改动 → 重新构建 → exe 哈希变化
   ├─ SmartScreen/基于信誉的保护 的"本机信誉"按文件哈希记账 → 归零
   ├─ 画像特征叠加：未签名 + 无版本资源 + Run 键持久化 + 全局键盘钩子 + 位于同步目录
   └─ 登录时由 Explorer/门禁拉起 → 被判定为"无法识别的应用"→ 阻止运行
```

这解释了"为什么偏偏在改完图标之后出现"——**改图标必然触发重编译，而重编译必然换哈希**。

### 3.2 为什么不是 Defender 杀毒引擎

若为引擎查杀，必然在 `Get-MpThreatDetection` 留下 `ThreatID`/`ThreatName` 与 `Resources`（清空历史通常也需要管理员操作）。
当前历史为空，且 Defender Operational 日志无 GetUp 事件 → 引擎未参与。

## 四、问题 2：进程存在但托盘无图标

### 4.1 主因（与问题 1 同源）

门禁在**进程创建之后**才做出阻断/挂起决定（云端信誉查询有延迟）。这段时间内：
- 任务管理器能看到进程对象 ✔（与你的描述一致）
- 应用尚未执行到 `self._tray.show()`（`main.py:85`）→ 托盘无图标 ✔（与你的描述一致）
- 随后进程被挂起或终止；若被终止，Explorer 甚至会撤掉图标

### 4.2 次要可能（需按第五节逐项排除）

| 可能 | 判据 |
|---|---|
| Explorer 托盘状态与旧条目不同步（条目建于 07-30，二进制已换哈希） | 删除 `NotifyIconSettings` 条目后重启 exe，看是否重建 |
| 三显示器下看错任务栏（Win11 默认仅在**主**显示器任务栏显示托盘） | 系统有 3 块屏：1920×1080 主屏 / 1920×1200@125% / 1080×1920@125% 竖向 |
| 冻结包静默失败（`console=False` 吞掉 traceback，只留一个隐藏的错误框） | 临时 `--console` 构建一版看输出 |

### 4.3 一个已排除但值得降噪的点

`GetUp.ico` 的 7 个目录项全部使用 **PNG 载荷**（16/24/32/48/64/128/256）。
PNG-in-ICO 官方仅定义用于 256×256，小尺寸用 DIB 是 Windows 惯例。
**这不是本次拦截的根因**（PE 资源结构已校验正确，且托盘图标由 Qt 画位图、与 exe 资源无关），
但它属于"非典型资源"，建议顺手规范化以降低解析器的可疑度。

## 五、验证清单（按顺序执行，每步都有明确判定）

### 步骤 1｜判定托盘是否真的注册成功（决定性）

```powershell
# 删掉旧条目，让 shell 重新登记
Remove-Item 'HKCU:\Control Panel\NotifyIconSettings\13829883633019532994' -Recurse -Force

# 手动启动一次 dist\GetUp\GetUp.exe，等待 10 秒，然后：
Get-ChildItem 'HKCU:\Control Panel\NotifyIconSettings' | ForEach-Object {
  $p = Get-ItemProperty $_.PSPath
  if ($p.ExecutablePath -like '*GetUp*') {
    "条目已重建: $($_.PSChildName)  IsPromoted=$($p.IsPromoted)"
  }
}
```

- **有输出** → 应用执行到了 `QSystemTrayIcon.show()`，注册成功 → 问题在 shell 显示侧（转步骤 4）
- **无输出** → 应用从未走到 `tray.show()` → 启动被拦截或静默失败（转步骤 2、3）

### 步骤 2｜判定进程是"被挂起"还是"在正常运行"

```powershell
Get-Process GetUp | Select-Object Id, Responding, StartTime,
  @{n='CPU';e={$_.CPU}}, @{n='Threads';e={$_.Threads.Count}}, @{n='WS_MB';e={[math]::Round($_.WorkingSet64/1MB,1)}}
```

- `Responding=False` 或 `Threads` 极少（<5）→ 被挂起/卡在启动阶段
- `Responding=True` 且线程数正常（十几~几十）→ 应用在运行，问题在 shell 显示侧

### 步骤 3｜锁定拦截者（一锤定音）

1. 打开 **Windows 安全中心 → 保护历史记录**（`Start-Process 'windowsdefender://threat'`）
   - 若出现 GetUp.exe 记录且来源为 **SmartScreen / 基于信誉的保护** → 确认问题 1 结论
   - 若来源为 **Defender 防病毒** 并给出威胁名（常见 `Trojan:Win32/Wacatac.B!ml` 之类）→ 属 PyInstaller + pynput 的已知误报族，改按第 6.4 条处理
2. 交叉验证：`Get-MpThreatDetection`（应仍为空）、`Get-WinEvent -LogName 'Microsoft-Windows-SmartScreen/Operational' -MaxEvents 20`

### 步骤 4｜判定 shell 显示侧

```powershell

# 4b. 确认是否只在主显示器任务栏显示托盘
```

## 六、修复思路

### 6.1 立即解除拦截（见效最快）

```powershell
# 需管理员：给发布目录加排除项（同时覆盖后续重新构建的产物）
Add-MpPreference -ExclusionPath 'C:\Users\ShangKeQian\OneDrive\Desktop\GetUp\dist\GetUp'
```

若弹窗是 SmartScreen 的「Windows 已保护你的电脑」：点 **更多信息 → 仍要运行**，
本机信誉会按新哈希重新积累。

### 6.2 把 exe 移出 OneDrive 同步目录（强烈建议）

```powershell
# 自启动与日常运行都指向本地目录，避开云同步的 MOTW/占位符与行为监控
$dst = "$env:LOCALAPPDATA\Programs\GetUp"
New-Item -ItemType Directory -Force $dst | Out-Null
Copy-Item 'C:\Users\ShangKeQian\OneDrive\Desktop\GetUp\dist\GetUp\*' $dst -Recurse -Force
# 然后在 GetUp 设置里重新勾选"开机自启动"，让 Run 键指向新路径
```

同步目录内的可执行文件会被持续重写 mtime/属性，且可能被赋予下载来源标记，
是启动拦截与"文件被占用"的双重风险源。

### 6.3 补齐 PE 元数据 + 规范化图标（降噪）

1. **加版本信息资源**（`build.py` 增加一个 `version_info.txt`）：

```python
# version_info.txt
VSVersionInfo(
  ffi=FixedFileInfo(filevers=(2,2,0,0), prodvers=(2,2,0,0), mask=0x3f, flags=0x0),
  kids=[StringFileInfo([StringTable('080404b0', [
      StringStruct('CompanyName', 'ShangKeQian'),
      StringStruct('FileDescription', 'GetUp - 久坐提醒'),
      StringStruct('FileVersion', '2.2.0.0'),
      StringStruct('ProductName', 'GetUp'),
      StringStruct('OriginalFilename', 'GetUp.exe'),
  ])]), VarFileInfo([VarStruct('Translation', [0x0804, 1200])])]
)
```

```bash
# build.py 增加
"--version-file", "version_info.txt",
```

2. **规范化 ICO**：`make_icon.py` 只让 256×256 用 PNG，其余尺寸写 DIB。
   最省事的做法是构建期用 Pillow 合成（Pillow 只作为**构建期**依赖，不进运行期）：

```python
# make_icon.py（构建期辅助，需 pip install pillow）
from PIL import Image
imgs = [Image.open(p) for p in ["icon_256.png", "icon_128.png", ..., "icon_16.png"]]
imgs[0].save("GetUp.ico", format="ICO", sizes=[(s, s) for s in (16,24,32,48,64,128,256)])
```

3. **代码签名（终局方案）**：OV/EV 证书 + `signtool sign /fd sha256 /tr <时间戳服务>`。
   签名后 SmartScreen 依据发布者信誉而非哈希，重编译不再重置信誉——这是唯一能根治问题 1 的手段。

### 6.4 降低行为画像的可疑度（若步骤 3 确认为引擎查杀）

`detectors/presence.py::start()` 用 pynput 安装**全局低级键鼠钩子**，这是键记录器的特征 API，
也是 PyInstaller + pynput 组合被 Defender 误报为 `Wacatac.B!ml` 的已知原因。

可选替代：改用 `GetLastInputInfo()` 轮询空闲时长（Win32，~10 行 ctypes，无需钩子、
无需额外依赖，且 CPU 开销低于常驻钩子），只在需要精确按键语义时保留 pynput。

### 6.5 托盘图标侧的加固（问题 2 若确认为显示侧）

1. 在 `SystemTray.__init__` / `main.py` 增加一次可观测的自检，便于日后定位：

```python
# main.py，self._tray.show() 之后
if not self._tray.isVisible() or not QSystemTrayIcon.isSystemTrayAvailable():
    print("[GetUp] 托盘不可用：explorer 可能未就绪", file=sys.stderr)
```

2. 处理 `WM_TASKBARCREATED`（explorer 重启后重注册）。Qt 一般会自行处理，
   但若步骤 4a 后发现"重启 explorer 后图标消失"，需显式重挂：

```python
# main.py，构造托盘前
from PySide6.QtWidgets import QSystemTrayIcon
self._app.commitDataRequest  # 占位：Qt 无直接信号时，用 QTimer 轮询 isVisible() 兜底
QTimer(self._app, timeout=lambda: (self._tray.show() if not self._tray.isVisible() else None))
```

### 6.6 不要再动的部分

`319d62c`、`8fd190e`（排除 matplotlib、消除启动期 `%TEMP%` 字体缓存目录）方向正确，
已实测 `%TEMP%` 无残留。**保留**——"启动时在 %TEMP% 反复创建目录"本身就是行为监控的高危特征。
